## Preservation and verification

The original executable automation and script objects were compared against the private source snapshot. Actions, templates, ordering, targets, thresholds, delays, execution modes and payloads remain unchanged. Presentation metadata is now in English. The 126 previously missing automation IDs were registered using the old aliases before applying the final names; four existing IDs were retained. The entity registry confirms the intended ID-to-entity mapping for all 130 automations. Existing references therefore continue to address the same entities.

The formerly disabled family-leaving automation remains disabled; the other 129 managed automations remain enabled. Three mapping-shaped automation files that HA's list loader ignored and two comment-only files were archived outside the include path. Root YAML cleanup preserves the effective configuration, extracts the recorder connection string into a local secret and removes an ignored recorder setting. Shadowed helper definitions and duplicate theme properties were resolved according to their previously effective values.

Verification included:

- Exact source hashes before promotion; 153 non-hidden source files had no concurrent changes.
- Clean, pinned repository builds; checks of staged and installed configuration using the actual HA version and installed custom integrations.
- Identity, name, mode and enabled-state checks after both reload phases and during subsequent observation.
- Live checks of all 54 script icons and registered service descriptions, plus all six parameter fields. HA's added text-selector defaults were normalized before comparison.
- Six managed automations naturally acquired a new `last_triggered` timestamp during the first observation window. This confirms execution, not successful delivery to every physical target. No device action was manually invoked as a test.
- Unchanged pod UID and spec, with restart count zero before and after. Existing storage, integration accounts, radio access, broker, node and container image were preserved.

Reloads were limited to scripts, two automation phases and themes. No MQTT reload, Home Assistant restart, broker restart or hardware-setting write was performed. Automation reloads reattach triggers and reset pending `for` timers; idle state exports cannot prove the absence of those timers. The runbook includes fresh running-action checks immediately before each reload.

## Existing problems requiring follow-up

The migration is complete; the installation still has inherited dependency failures. The [runtime dependency inventory](../runtime-dependencies.json) describes its exact scope and source snapshot:

- **61 missing entity references**, **46 existing but unavailable entities**, and **four missing notification services** across the active configuration. These counts describe the original snapshot, not a guarantee of current device availability.
- The absent destinations are `notify.chrome`, `notify.mobile_app_als_iphone2`, `notify.pushbullet` and `notify.living_room_tv`. Replacement destinations require the exact intended household devices/accounts. Existing targets were retained.
- A stored zero-grid dashboard references an already absent automation; there is no verified equivalent to substitute. See [ownership and references](../architecture.md).
- The inherited `/config/kodi` helper is missing. Several media/camera dependencies and preserved legacy templates need their actual provider/caller contracts verified before changing behavior.
- The recurring MQTT Number error is diagnosed: Cerbo's dynamic BatteryLife limit reports five while the legacy HA number permits 20–90. Widening its range would also widen its write interface, and MQTT reload affects all YAML MQTT entities. The [read-only diagnosis](../mqtt-number-diagnosis.md) records producer evidence and bounded remediation options. Current control behavior is preserved.

Native schema checks and repository tests do not establish end-to-end delivery of every notification, media stream, lighting action, irrigation action or energy-control decision. Device/provider acceptance remains separate from this migration's source and runtime identity checks.
